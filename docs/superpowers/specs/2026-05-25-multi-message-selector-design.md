# Multi-Message Selector — Design Spec

**Date:** 2026-05-25  
**Status:** Approved  

---

## Context

The XSD Visualizer currently supports a single hardcoded message type (`pain.001.001.09`), comparing the ISO 20022 original against the Georgian national adaptation. The business requirement has expanded: multiple ISO 20022 message types will be supported, each with its own ISO XSD and Georgian (`GEO_`) XSD. The viewer needs a way to select which message to compare.

---

## Goals

- Support any number of ISO 20022 message types, each with ISO + Georgian XSD pair.
- Auto-discover available messages from folder structure — no manual config editing when adding a new message.
- Add a dropdown in the viewer to switch between message types.
- Keep all existing viewer features (diff, language toggle, filters, search) unchanged.

---

## Non-Goals

- Arbitrary left/right pairing across different message types (not needed).
- Exposing revision files in the selector (revisions remain quiet reference files).
- Two-dropdown comparison within a message type.

---

## Section 1 — XSD Folder Structure

Each subfolder under `xsds/` represents one message type. The subfolder name **is** the message ID.

```
xsds/
  pain.001.001.09/
    pain.001.001.09.xsd                    ← ISO 20022 original (no prefix)
    GEO_pain.001.001.09.xsd                ← Georgian adaptation (GEO_ prefix)
    GEO_pain.001.001.09.revision_0.3.xsd   ← quiet reference, ignored by build
    GEO_pain.001.001.09.revision_0.4.xsd   ← quiet reference, ignored by build
    GEO_pain.001.001.09.revision_0.5.xsd   ← quiet reference, ignored by build
  pain.002.001.xx/                         ← future message, same convention
    pain.002.001.xx.xsd
    GEO_pain.002.001.xx.xsd
```

**Discovery rule:** A folder is a valid message if it contains **both**:
- `<folder-name>.xsd` (ISO original)
- `GEO_<folder-name>.xsd` (Georgian adaptation)

Any other files in the folder (revisions, extras) are silently ignored by the build script.

## Section 2 — Generated Output Structure

```
viewer/
  data/
    messages.json                          ← manifest (auto-generated by build.py)
    pain.001.001.09/
      original.json                        ← parsed ISO XSD
      original.js                          ← .js sidecar for file:// fallback
      schema-model.json                    ← parsed Georgian XSD
      schema-model.js
      diff-model.json                      ← diff between ISO and Georgian
      diff-model.js
    pain.002.001.xx/                       ← generated when folder exists in xsds/
      original.json
      original.js
      schema-model.json
      schema-model.js
      diff-model.json
      diff-model.js
  index.html   (static — minor: add dropdown element)
  app.js       (updated — manifest load + dynamic data paths)
  styles.css   (updated — dropdown styling to match header aesthetic)
```

The viewer derives all data paths from the message ID. No lookup table in app.js.

**`viewer/data/messages.json` format:**

```json
{
  "messages": [
    { "id": "pain.001.001.09", "label": "pain.001.001.09" }
  ]
}
```

Fields:
- `id` — used to construct data paths (`data/<id>/original.json`, etc.)
- `label` — display text in the dropdown

## Section 3 — Build Script (`build.py`)

Replace `generate.bat` with a cross-platform Python build script. Keep `generate.bat` as a thin wrapper (`python build.py`) for backward compatibility.

**`build.py` algorithm:**

1. Scan `xsds/*/` for subdirectories.
2. For each subdirectory, check if both `<id>.xsd` and `GEO_<id>.xsd` exist.
   - If not, print a warning and skip.
3. For each valid message `<id>`:
   ```
   python parser/parse_xsd.py \
     --input xsds/<id>/<id>.xsd \
     --out viewer/data/<id>/original.json

   python parser/parse_xsd.py \
     --input xsds/<id>/GEO_<id>.xsd \
     --out viewer/data/<id>/schema-model.json

   python parser/diff_xsd.py \
     --old viewer/data/<id>/original.json \
     --new viewer/data/<id>/schema-model.json \
     --out viewer/data/<id>/diff-model.json
   ```
4. Write `viewer/data/messages.json` from the collected list of valid message IDs.
5. Print a summary of messages processed.

**CI workflow** (`.github/workflows/deploy.yml`): Replace the three hardcoded parser calls with `python build.py`. The `viewer/` deploy step is unchanged.

## Section 4 — Viewer UI Changes

### `index.html`

Add a `<select id="message-selector">` element in the header, to the **left** of the existing language switcher. It is hidden via CSS when only one message is available.

Header layout (left → right):
```
[ pain.001.001.09 ▾ ]   [ EN | KA ]   [ ISO 20022 | Georgian | Diff ]   [ 🔍 search ]
```

### `app.js`

- **On page load:** `fetch("data/messages.json")`, then:
  - Populate `<select id="message-selector">` with one `<option>` per message.
  - If only one message, hide the selector element.
  - Call `loadData(messages[0].id)` to load the first message.
- **`loadData(messageId)`** — replaces all hardcoded filenames:
  - Fetches `data/<messageId>/original.json` (+ `.js` fallback)
  - Fetches `data/<messageId>/schema-model.json` (+ `.js` fallback)
  - Fetches `data/<messageId>/diff-model.json` (+ `.js` fallback)
  - Resets view state: selected node, search query, expanded set, view mode.
- **Dropdown `change` event:** calls `loadData(selector.value)`.

### `styles.css`

- Style `#message-selector` to match the existing header pill/button aesthetic (font, border-radius, colors).
- `#message-selector.hidden { display: none; }` for single-message deployments.

---

## Migration

One-time steps (done manually, not by `build.py`):

1. Move `xsds/*.xsd` files into `xsds/pain.001.001.09/` (the new subfolder).
2. Delete the old `viewer/original.json`, `viewer/original.js`, `viewer/schema-model.json`, `viewer/schema-model.js`, `viewer/diff-model.json`, `viewer/diff-model.js` from the viewer root — `build.py` will regenerate them at `viewer/data/pain.001.001.09/` instead.

`generate.bat` becomes a thin wrapper (`python build.py`) for backward compatibility.

---

## Testing

Existing pytest suite (`tests/`) uses fixtures and `samples/` — no `xsds/` path references, so it is unaffected by the folder restructure. No new tests are required for this change, but manual verification steps are:

1. Run `python build.py` → confirms `viewer/data/messages.json` and per-message folders are created.
2. Open `viewer/index.html` via local HTTP server → confirms dropdown appears and loads pain.001.001.09 data.
3. Add a second dummy message folder to `xsds/` → confirms it appears in the dropdown after re-running `build.py`.
4. Remove one of the two required XSDs from a folder → confirms build.py warns and skips it.
