```bash
# Install dependencies
pip install -r requirements.txt

# Build all viewer data (auto-discovers xsds/ subfolders)
python build.py

# Run tests
pytest tests/ -v

# Run a single test
pytest tests/test_diff_xsd.py::test_added_node -v

# Serve viewer locally
cd viewer && python -m http.server 8080
# open http://localhost:8080

# Parse a single XSD manually
python parser/parse_xsd.py --input xsds/pain.001.001.09/pain.001.001.09.xsd --out viewer/data/pain.001.001.09/original.json
python parser/diff_xsd.py --old viewer/data/pain.001.001.09/original.json --new viewer/data/pain.001.001.09/schema-model.json --out viewer/data/pain.001.001.09/diff-model.json
```

## Architecture

Three-stage pipeline: XSD files → Python parsers → JSON models → static browser viewer.

```
xsds/<message-id>/          ← source XSD files (one subfolder per message type)
  <message-id>.xsd          ← ISO 20022 original
  GEO_<message-id>.xsd      ← Georgian national adaptation (main)
  GEO_*.revision_*.xsd      ← revision history (ignored by build)

parser/
  schema_model.py           ← TypeRegistry (pass 1) + NodeBuilder (pass 2); two-pass XSD → node tree
  parse_xsd.py              ← CLI: XSD → schema-model.json + .js sidecar
  diff_xsd.py               ← CLI: two schema-model.json files → diff-model.json + .js sidecar

build.py                    ← auto-discovers xsds/*/ folders, runs parsers, writes viewer/data/ + manifest

viewer/
  data/
    messages.json           ← manifest: list of available message IDs (generated by build.py)
    messages.js             ← JS sidecar for file:// fallback
    <message-id>/
      original.json + .js   ← parsed ISO original
      schema-model.json + .js ← parsed Georgian adaptation
      diff-model.json + .js ← diff between the two
  index.html                ← static shell; no framework
  app.js                    ← all viewer logic (~800 lines vanilla JS)
  styles.css                ← all styling
```

## Key Data Flow

1. `build.py` scans `xsds/*/` — a folder is valid if it contains **both** `<id>.xsd` and `GEO_<id>.xsd`.
2. For each valid folder it calls `parse_xsd.py` twice (ISO + GEO) then `diff_xsd.py`.
3. Writes `viewer/data/<id>/` output files and regenerates `viewer/data/messages.json`.
4. On page load, `app.js` fetches `data/messages.json`, populates the message-selector dropdown, then calls `loadData(messageId)` for the first entry.
5. `loadData(messageId)` fetches `data/<id>/original.json`, `data/<id>/schema-model.json`, `data/<id>/diff-model.json` in parallel. Falls back to `.js` sidecars when served via `file://`.

## Parser Internals

`schema_model.py` builds the node tree in two passes:

- **Pass 1 — TypeRegistry**: walks all `xs:complexType`, `xs:simpleType`, `xs:element` definitions; extracts children, attributes, enumerations, restrictions, and ISO label from `source="Name"` annotations; supports dual EN/KA documentation.
- **Pass 2 — NodeBuilder**: recursively expands from the root element; detects cycles using both XML path and type-name keys; converts `xs:attribute` to child nodes prefixed with `@`; assigns stable SHA1-based node IDs.

Each node has: `id`, `parentId`, `xmlPath`, `xmlTag`, `label`, `typeName`, `nodeKind`, `multiplicity`, `isMandatory`, `isRepeating`, `documentation`, `documentationKA`, `restrictions`, `enumerations`.

`diff_xsd.py` matches nodes by xmlPath first, then by (parent + xmlTag), then by (parent + typeName). Unmatched → Added/Removed. The Georgian profile only constrains — it never contradicts ISO — so all changes are classified NonBreaking or Informational (never Breaking).

## Viewer app.js Structure

```
state {}             ← single global state object (schema, diff, filters, expanded, selected, loadToken)
init()               ← entry point: fetch manifest → populateSelector → bindUI → loadData
loadData(messageId)  ← fetch/parse all three JSON files; includes loadToken race-condition guard
setupViewSelector()  ← show/hide ISO 20022 / Georgian / Diff buttons based on available data
switchView(mode)     ← switch between original/updated/diff; resets navigation state
bindUI()             ← register all event listeners (called once from init)
renderTree()         ← rebuild the DOM tree from state; flat or hierarchical depending on search
selectNode(id)       ← update selection + render details panel
initDiff()           ← index diff changes by xmlPath and nodeId; build removed-ghost-node maps
```

`bindUI()` is called once from `init()`. Never call it from `loadData()` or `switchView()`.

The `.js` sidecar files (`original.js`, `schema-model.js`, `diff-model.js`) each write a single global variable (`window.__SCHEMA_MODEL__` or `window.__DIFF_MODEL__`). The sidecar fallback in `loadSidecar()` is sequential — not parallel — because both `original.js` and `schema-model.js` write to the same global.

## Adding a New Message Type

1. Create `xsds/<message-id>/` containing `<message-id>.xsd` and `GEO_<message-id>.xsd`.
2. Run `python build.py`.
3. The dropdown appears automatically — no code changes needed.

## CI / Deployment

`.github/workflows/deploy.yml` runs `python build.py` then deploys `viewer/` to GitHub Pages on every push to `main`. The `viewer/data/` directory is generated at deploy time and is **not** committed.

## Tests

Tests live in `tests/` and use pytest fixtures from `conftest.py`. They use `samples/sample_mini.xsd` as a fixture — they do **not** reference files under `xsds/`. Safe to run without having built the viewer data.
